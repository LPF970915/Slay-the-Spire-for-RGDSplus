# P0 双屏目标设计与缺漏检查

日期：2026-09-20。状态：**用户已明确确认 P0 通过，授权开始卡二独立 P1 几何原型。**

P1 的实现、操作与证据见 [P1 几何原型](P1_GEOMETRY_PROTOTYPE.zh-CN.md)。
本文件保留已批准的设计约束，不把原型通过等同于真实游戏双屏适配完成。

本文的 P0 是双屏设计准备阶段，对应此前预研文档的 R0；
与历史单屏 P0 启动里程碑、缺陷严重度 P0 无关。
详细的 U01～U33 界面表、坐标与瞄准方案见
[双屏界面分配与跨屏瞄准预研](DUAL_SCREEN_INTERFACE_RESEARCH.zh-CN.md)。

## 1. 已确认的目标

| 项目 | P0 设计决定 |
| --- | --- |
| 上屏主体 | 背景、角色/敌人、战斗与过场动画、目标反馈 |
| 顶部工具/状态栏 | 保持原生上屏顶端位置，包括原有药水、地图/牌组/设置入口与遗物区域；不复制下屏常驻栏 |
| 顶栏交互 | 原生手柄导航/检视/激活为主，必要时补上下文按键提示；纯触摸全流程不是本方案目标 |
| 下屏主体 | 手牌、能量、结束回合、牌堆、房间/页面按钮、候选项与确认/取消 |
| 下屏底图 | 当前界面原生最底层背景/远景，不使用最终游戏画面的截图 |
| 战斗前景 | 原生装饰前景迁移到下屏，位于手牌和控件后方；上屏不再绘制这些前景 |
| 原生手柄战斗 | 左右选牌→A→左右选敌→A，B 取消；保持可独立完成战斗 |
| 触摸战斗 | 向上拖牌的方向选择上屏敌人，高亮和目标提示同步；合法松手才提交 |
| 跨屏箭头 | 一条路径分别裁剪到上下屏，铰链留空；先正确选敌，再追求曲线效果 |
| 数据与运行 | 一份规则状态、一次逻辑更新；稳定单屏可回退，正版/正式存档不改动 |
| 当前实施范围 | 卡二独立、无游戏资源的 P1 几何原型；不覆盖稳定单屏，不访问正式存档 |

“顶栏保留”只适用于原游戏本来显示顶栏的场景；不改变原生隐藏和禁用条件。

## 2. 补齐的交互边界

### 2.1 顶栏入口与打开的页面不是同一归属

| 操作 | 入口与局部反馈 | 打开的内容 | 返回约定 |
| --- | --- | --- | --- |
| 地图 | 上屏地图入口/手柄快捷动作 | 下屏可交互地图，上屏总览 | 返回进入前场景与焦点 |
| 总牌组 | 上屏牌组入口/快捷动作 | 下屏牌组网格，上屏当前卡牌详情 | 不清空原手牌的选择历史 |
| 设置 | 上屏设置入口/Start | 下屏设置、确认框 | 返回原场景，不把同一 B 再传给战斗 |
| 药水 | 上屏药水槽、原生使用/弃置菜单 | 原生上屏手柄选项及选敌反馈 | 取消不消耗药水，完成后恢复原焦点 |
| 满槽奖励药水 | 下屏奖励条目 | 原生药水处理/替换流程仍用上屏槽位与手柄 | 返回奖励页；不误领奖或误弃置 |
| 遗物、金币、HP 等 | 原生上屏检视与说明 | 局部说明留上屏；独立详情页按 U25 分配 | 说明关闭后恢复原焦点 |

药水的选敌箭头留在上屏，不从下屏手牌区凭空出现。
卡牌与药水可共享目标身份/显示服务，但必须分开 owner、提交及取消生命周期。
顶栏局部菜单不因为“按钮一般在下屏”而被强制拆散。

### 2.2 当前按键证据与缺口

本轮核对了本地 `slay.gptk`、Java 桥接和正版 `CInputActionSet` 默认动作。
以下是默认配置的静态对应，不等于双屏实机功能已通过；用户重映射应读取实际绑定。

| 按键 | 当前默认动作 | 后续必须验证 |
| --- | --- | --- |
| X | `topPanel` / 查看模式 | 顶栏与遗物进入/退出、各方向导航范围 |
| 短 Select | `map` | 打开/返回地图；不破坏长按约 1.5 秒应急退出 |
| Start | `settings` | 设置和嵌套确认框返回 |
| L1 | `pageLeftViewDeck` | 牌组与页面上下文中的原生语义 |
| L2 / R2 | `drawPile` / `discardPile` | 保持已有抽/弃牌堆修复 |
| 方向 / A / B | 原生导航、选中、取消 | 顶栏、药水和战斗选敌不可重复消费 |

没有假定 X 能直接到达每一种信息。长遗物栏滚动、球/姿态、敌人状态、计时/进阶说明、
药水替换和只读数值的提示，都需逐项证明手柄可达。
缺少映射时先补原生动作的按键路径，再补提示；**提示不能代替缺失的功能**。
不提前占用 Select 长按、B 取消和卡牌/牌堆按键，也不默认为设备已有右摇杆检视映射。

按键提示只在相关焦点/菜单出现，优先用游戏现有图标；按设备机身与实际绑定验证，
不直接把 PC 键盘字母画成掌机按钮提示。

### 2.3 焦点与误触

- 同时只有一个有效焦点：战斗手牌、敌人选中、上屏顶栏、药水菜单、下屏页面或模态框。
- 顶栏接管前取消触摸拖牌；原生禁止切换时不强行进入顶栏。
- 顶栏局部菜单活动时下屏触点不能同时出牌；退出后需新的按下事件才能开始操作。
- 上屏入口打开下屏完整页面时，输入跟随页面；B 只返回一层。
- 从下屏奖励进入药水槽处理，结束后恢复奖励页，不丢弃未领取条目。
- 显示检视状态与原生逻辑使用同一焦点；不能只是把光标画在上屏，真实 hitbox 仍选着下屏卡牌。
- 全屏转场、敌人回合、模态页遵循原禁用条件；触摸丢失、旧 UP、B+A 同帧等仍按手势身份处理。

## 3. 下屏背景覆盖

将用户的“最后一层背景”统一解释为**视觉最底层背景/远景**，不解释为最后一次 draw。
背景图层可供两屏复用，背景状态只更新一次；复制背景展示不等于再执行一次场景更新。
不能为了取一张底图重开房间、重新随机场景装饰或额外播放音效。

| ID / 界面族 | 下屏底图来源与处理 | 特别禁止 |
| --- | --- | --- |
| B01 启动、主菜单、角色选择、自定义、档案 | 当前原生场景的最底层背景；不带角色、Logo、菜单控件 | 不能把整帧缩小铺在按钮后面 |
| B02 战斗及战斗奖励 | 当前幕/房间的原生底层背景，再叠迁移的装饰前景；奖励叠原生遮罩/面板 | 上屏不再保留同一装饰前景；不移走人物脚下必要地面 |
| B03 地图 | 当前页面的原生底图，地图纸面保留在可操作地图层 | 不把节点/路线烘焙进背景导致点击与视觉脱节 |
| B04 商店、营火、宝箱 | 当前场景的原生底层背景；可独立分离的装饰按页面定义复用 | 不把商人、篝火操作图标、可开宝箱误算成纯背景 |
| B05 事件、涅奥、小游戏 | 当前事件/对话原生背景；插图按 U06/U21 留上屏，小游戏操作对象留下屏 | 不把可点击卡片/机关压进只读底图 |
| B06 牌堆/详情/选牌、设置、教程/弹窗 | 沿用调用者当前原生场景底图，叠加原生遮罩与面板 | 弹窗不是新房间；关闭不残留遮罩或重置背景动画 |
| B07 图鉴、历史、统计、制作名单、更新说明、在线入口 | 当前原生菜单/页面最底层背景；无独立背景则继承合法父场景 | 不擅自加无关战斗背景，也不伪造在线页面 |
| B08 死亡/胜利、章节/终章、解锁、未知页面 | 已识别页面采用自身原生背景和过渡；未知页完整下屏降级 | 不抢显示上一幕缓存、不强开按钮 |

完整下屏降级是明确的兼容模式，不是背景拆分成功：
若降级页面带原生顶栏，则顶栏随完整页显示且仅一份可交互实例，上屏不再叠一套同类控件。
这是未适配场景的临时例外，须记录；不能用它替代已适配战斗的“顶栏固定上屏”验收。

## 4. 分层安全边界

本轮确认四幕场景类提供 BG/FG 绘制入口，但同一场景还存在中景、地面、光效、
随机布景选择等字段；“有 BG 方法”不等于已经找到一张可直接铺满下屏的完整底图。
具体素材/绘制批次归属仍是后续接入任务，不在 P0 伪称完成。

| 内容 | 归属 / 原则 |
| --- | --- |
| 最底层背景 | 两屏可显示同一原生资源；按本场景已选变体读取，不额外随机 |
| 中景/地面/必要墙体 | 上屏保留战斗空间；下屏仅在底图透明或不完整时补必要的原生背景子层 |
| 装饰性近景、下沿遮挡物 | 迁移到下屏背景之上、操作内容之下，上屏隐藏 |
| 角色阴影、攻击范围、敌人意图、目标高亮 | 上屏战斗信息，不按贴近屏幕底部就归入前景 |
| 火焰/雾/尘埃等背景效果 | 按宿主层归属；复用显示需确认绘制无副作用，状态只更新一次 |
| 手牌、抽/弃/消耗牌动画 | 下屏；不被装饰前景盖住 |
| 顶栏与遗物/药水效果 | 跟随上屏真实控件位置，不能飞向旧下屏位置 |
| 跨屏箭头 | 覆盖两屏相关内容但不挡必要读数，受最高层模态/过渡遮罩约束 |
| 全屏暗化、闪白、章节切换 | 使用同一时序；是否覆盖两屏按原语义定义，不各自推进动画 |

按原生 4:3 比例显示底图，不将带边框的 UI 背景当成可任意拉伸纹理。
透明/局部背景以该场景自身的底色和必要原生背景子层补齐，不能读到上一帧未清空像素。
禁止每帧 CPU 截图回读；若采用缓存，房间、章节、页面、背景变体、分辨率变化时失效。
保存/恢复 viewport、scissor、矩阵、blend、shader 与 framebuffer，不能污染卡牌或字体。
不为了压住背景而统一把下屏涂黑；亮度与遮罩优先沿用当前页面原生规则。

## 6. 通过条件与下一步边界

P0 通过需确认以下设计：

1. 顶栏及其局部菜单保留上屏，手柄为主要入口；下屏不强制复制，接受非纯触摸方案。
2. 下屏使用本界面原生底层背景；战斗装饰前景下移，上屏不保留副本。
3. 顶栏打开的完整页面仍按功能下屏交互，焦点返回和药水例外如第 2 节。
4. 前景不包含必要地面/阴影/战斗信息；背景无副作用复用、无残帧、不卡住页面。
5. 未适配页面允许明确的完整下屏兼容例外，不静默漏掉交互。
6. 同意后续先做无游戏资源的几何交互原型，而不是直接改掌机游戏。

**当前结论：2026-09-20 用户已明确确认 P0 通过，进入 P1（旧称 R1）。**

通过后的 R1 只验证：上下屏几何、目标位置、拖动方向、目标歧义、按键兜底、
跨屏路径及输入取消。使用抽象卡牌/目标，不复制正版素材，不访问存档。
P0 的背景资源提取、真实手柄覆盖和性能问题留在后续隔离接入阶段验证，
几何原型不得宣称这些事项已通过。
