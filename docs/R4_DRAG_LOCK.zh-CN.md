## 1. 用户反馈与设计

用户报告此前版本完成两轮、每轮三关战斗，未遇明显问题。
唯一明确反馈为角度选敌过严，继续上提或未对准时虚线向高处延伸。
这是局部实体游玩证据，不代表复杂卡牌、全流程性能、音频或长稳验收通过。

用户随后确认采用以下交互：

- 持续按住即可拖牌，不增加强制长按等待。
- 相对拿起时的位置上移 24 px 激活，首次按卡牌中心至敌人中心的虚拟双屏
  直线距离锁定最近敌人；虚拟坐标包含 48 px 屏间距。
- 锁定后，继续上下移动只改变卡牌位置与曲线，不按角度重新选敌。
- 横向累计移动 64 px 切换一个相邻敌人，按屏幕 X、Y、原生列表顺序稳定排序。
  大位移可一次跨过多个目标，停住不会继续切换，不在边缘循环。
- 拖回拿起位置或更低时解除锁定，但不结束手势；同一根手指再次上提可重新激活。
  初始抓取偏移保持不变，判断的是卡牌位移而非不同抓取点的绝对高度。
- 已激活后，只要仍高于拿起位置，就保留可出牌状态；24 px 激活/0 px 回拖形成缓冲。
- 在有效出牌区松手，先校验最终 UP 坐标、已显示目标和原生 `canUse`，
  再经原生 `playCard` 提交一次；否则回到手牌。
- 下屏最外 2 px 保留滑出保护：可以拖到边缘观察，但边缘松手取消。
  B、多指、失焦、断连、手柄接管仍取消；目标死亡/离场不能自动换敌后提交。

24/64 px 为本轮软件参数，不是实体手感验收结论。

## 2. 绘制和规则边界

- 单体敌人牌（含 SELF_AND_ENEMY）继续使用原生红色 TARGET_UI_CIRCLE /
  TARGET_UI_ARROW 和二次曲线；端点始终为当前锁定敌人的真实命中框中心。
- SELF 牌使用同一原生素材的灰色着色，连接上屏玩家角色。
  这不是声称原版所有自身牌本来就绘制该连线。
- 群体/无目标牌保留原生范围/自身反馈与合法性，不伪造单个敌人箭头。
- 触摸曲线限制控制点，避免曲线向上屏外远伸；手柄曲线保持原有算法。
- 没有锁定敌人时不再向上屏固定高度外推方向虚线。
- 一次游戏 update、一次原生 render；自身曲线仅追加 GPU 绘制，
  不额外调用角色/页面 render，不改变伤害、能量、随机结果或存档规则。

## 3. 代码与软件门禁

- `prototype/r3/java/rgds/r3/DragAim.java`：纯几何的激活/回拖/锁定/横向切换状态。
- `CombatTouch.java`：原生卡牌所有权、同手势重新激活、目标身份和单次提交。
- `DualRender.java` / `AimCurve.java`：原生素材、固定端点及灰色自身曲线。
- `DragAimTest.java`：阈值、重叠目标、目标丢失、边缘、偏移及 2,000 组竖向不变性。
- `UiTransformTest.java`：原生曲线回归和锁定曲线端点/边界检查。
- 历史 P1 与 AimPicker 的 2,000 组对照继续保留，不再称为当前实时选敌算法。
- `device.py run --silent` 为显式单次静音开关，与 `--audio` 互斥。
  不改 R4 默认有声策略、不改用户音量偏好，review 默认仍静音。
