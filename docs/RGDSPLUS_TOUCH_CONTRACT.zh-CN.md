## 2. 不可遗漏的生命周期

```text
独占会话锁 / 检查其他游戏
  -> 建立独立异常恢复进程
  -> 暂停本会话接管的菜单
  -> 读取已知 tpctrl 原值 (0/1)
  -> 原值写入恢复记录
  -> 显式写入 tpctrl=0（原值为 0 也写）
  -> 启动应用
  -> 获焦后读取 gt9xx-0 / 独占触摸
  -> 取消在途手势 / 释放触摸 / 停止本会话应用
  -> 当前 tpctrl 仍为 0 才恢复原值
  -> 恢复本会话暂停的同身份菜单
```

接口为 `/sys/class/anbernic_misc/tpctrl`。未知值、缺失或不可写时记录失败，
不能写猜测值，不能宣称触摸就绪。启用失败时真实游戏应保持可退出的按键路径，
且阻止把该次会话记为触摸验收成功。
正常退出、长按退出、启动失败和监护进程恢复都要覆盖；不能只靠 shell EXIT trap。
不承诺断电恢复，不修改永久配置，不主动改动系统菜单之后再次设置的模式。

基准代码：[模式启用与恢复](../prototype/p1/touch_mode.py)、
[会话监护](../prototype/p1/supervisor.py)。
真实游戏接入优先复用模式模块；若换成 C/JNI，必须逐项复现语义并重新跑实机验收，
不能只把一行 `echo 0` 加入启动器却遗漏恢复。

## 3. 输入不变量

1. 按 `device/name == gt9xx-0` 发现设备，不写死 `event1`。
2. ioctl 查询轴、槽与当前触点；物理坐标直接映射到下屏本地 1024×768，
   不减去合成器布局中的 1024，也不因上下屏交换而交换触摸轴。
3. Type-B 以 `SYN_REPORT` 为完整报告；保存槽内坐标以支持同位置连点。
4. 获焦才 `EVIOCGRAB`，失焦/退出释放；不独占手柄设备，保留独立退出。
5. 同一输入仅消费一次：使用 evdev 时不同时向游戏发送 SDL touch 和合成鼠标。
6. 第二指、失焦、丢事件、断连先取消；重同步先清队列，读取槽状态，
   未抬起的手指不得成为新手势。设备重连生成新的来源身份。
7. 最后的 UP 若带新坐标，先更新并校验；失效、未显示或歧义目标不可提交。
8. B 取消优先；手柄接管后旧触摸 UP 无权替手柄提交。
9. 每帧只有一份游戏状态更新。输入线程只投递事件，不能操作渲染或在后台调用出牌规则。

基准代码：[设备输入](../prototype/p1/device_input.py)。
按键兜底保留，触摸接入不得倒退已验收的长按 Select 退出。

## 5. 诊断顺序

先检查 `tpctrl before/requested/active/restored`，再检查焦点/独占与原始事件数量。
原始事件为 0 时不要先改游戏 hitbox；事件存在但无动作时查槽与阻塞状态；
动作存在但未命中时再查下屏坐标、层级和输入消费。
软件注入绕过实体面板，只验证其后的输入链路。
用户确认、原始实触、注入、回放、截图分别记录来源，不能互相替代。
