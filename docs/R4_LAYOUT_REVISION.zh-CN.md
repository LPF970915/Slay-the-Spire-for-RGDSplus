## 地图与箭头的几何约束

- 地图不是原图压扁，也不是两张同步滚动的相同截图。
  下屏显示原生逻辑 y=0..768，上屏显示 y=768..1536。
- 投影纵向减半配合 1536 高 viewport，抵消缩放，保持原生宽高比例与节点尺寸。
  下屏 viewport y=0，上屏 y=-768，同一批节点/路径几何提交到两个视口。
- 不改全局 `Settings.HEIGHT`，不改 `DungeonMapScreen.offsetY`，不运行第二套地图 update。
  图例/返回等 HUD 使用下屏本地 1024×768 坐标。
- 箭头使用 LibGDX 原有二次 Bezier 实现和原版控制点；起点跟随当前手牌，
  终点来自原生 hoveredMonster，末端保留原版越过目标高度后回弯的形状。
  虚拟坐标中保留既有 48 像素屏间距，同一曲线和分段位置投影到两屏。
- 箭身、箭头直接引用正版游戏加载的原生贴图，不提取进适配包，不再用金色细线替代。
  使用 `AbstractPlayer.ARROW_COLOR`、原版箭身渐大比例与 `Interpolation.elasticOut`。
  根据延长后的曲线长度增加分段，上限 96；弹性动画每帧只推进一次。
- 完整贴图四边形提交到两屏，由 GPU 裁切面板边缘，不因中心在屏间隙而漏掉边缘碎片。
  几何测试覆盖两侧/同列目标与屏边坐标，真实多目标、拖甩及选敌切换仍需补测。

## 当前小屏适配边界

本轮优先完成图层归属、连续视野、主菜单与公共按钮的尺寸调整。
没有宣称全部字号、长文、全部屏幕键盘、所有触摸 hitbox 已完成。
`smallControl` 登记相同仿射逆变换；当前 R4 已接入下屏实际点击与战斗拖牌，
不再是 capture-only。R3 与未显式启用 live 的 review 仍保留仅采集模式。
不能以静态逆变换或设备注入测试代替实体触点和逐页交互验收；
最新证据见 [R4 触控运行](R4_TOUCH_RUNTIME.zh-CN.md)。

下一轮用户可按 `Uxx + 截图 + 希望的移动/尺寸/图层` 反馈。
优先调版，再处理素材加载和触控反馈；若发现崩溃、误提交或无法退出则先修复。
