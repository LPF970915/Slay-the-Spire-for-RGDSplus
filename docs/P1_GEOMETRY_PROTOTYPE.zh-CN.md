## 0. 实体触摸回归修订

2026-09-20 用户报告卡二原型无法触摸。对照本地小丑牌项目的
`packaging/dual_touch.sh`、`platform/rgds_evdev.lua` 和公开移植指南第 5 节发现：
P1 已具备 evdev/坐标/独占处理，但遗漏了启动时显式写入固件 `tpctrl=0` 的步骤。
用户会话 `1789875162758097043.jsonl` 有获焦记录，但没有产生应用输入动作。
事后读取 `tpctrl` 为 0；没有记录该次启动的模式写入，不能仅凭读值排除启用问题，
也不能把本次发现直接判为已经实触证实的唯一根因。

`p1-geometry-20260920-touch2` 补齐：

- 先保存已知模式并写入恢复记录，再显式写入 0，即使原先读值也是 0。
- 正常退出、应急退出及独立启动器恢复进程都执行条件恢复；未知值不写，
  后续其他程序已改值时不覆盖。不承诺断电后执行清理。
- 原始触摸事件、报告和动作计数写入状态，附焦点、独占、阻塞与接触数量；
  每次会话最多记录前 128 个原始事件。
- 新增 6 项模式单测，本地和设备测试合计 29 项通过；正常启动/退出日志
  已确认 `before=0 requested=0 active=0` 和 `restored=0`。
- 实机冻结渲染后长按退出、强杀独立启动器后恢复，两条路径均记录
  `restored=0` 并回到系统菜单。软件注入另测到 28 个原始事件、12 个报告、
  1 次合法提交，仅作为诊断链路检查，不替代实体复验。

旧版的事件注入和回放绕过实体传感器，遗漏了此层验收。
因此原“软件输入通路通过”结论保留，但明确不代表实体触摸通过；
用户随后明确确认实触有效。会话 `1789876031465630404` 记录菜单启动
`before=1 requested=0 active=0`，退出 `restored=1`，并有实际触摸选敌提交。
这确认了当前触摸基线，不自动通过瞄准手感与精度验收。

### 0.1 aim3 拖牌区域修订

用户反馈拖动稍靠上虚线就消失。实际轨迹中可以看到相邻点
`(555,398)` 已选敌而 `(553,396)` 无目标，尚未接近物理边缘。
原角区间吸附过窄使敌人之间出现空档，箭头仅在有目标时绘制，放大了断线感觉。

aim3 调整：

- 向上激活门槛由 72 降到 48 像素；按方向划分更宽的目标吸附区，
  目标轮廓外最大吸附 0.14 弧度，邻目标间 0.035 弧度保持余量。
- 真正重叠的目标仍不猜测；明显偏离目标区不强行选中。
- 没有合法目标也保留灰色方向虚线；选中后为金色箭头和同身份高亮。
- 下屏有效坐标内持续瞄准，不再在顶部 12 像素处取消。浮动卡牌保持在画面内。
- 最外侧 2 像素处抬起仍视为边缘失联风险而取消，不将越屏丢触误作出牌。
  可以在距顶部 8 像素处完成松手提交，不要求手指离开下屏。
- 快速甩牌的 move/up 同帧时冻结目标，在下一次画面呈现该目标后提交一次，
  不能在松手之后重新挑敌；B、目标移除、失焦仍能取消。
- 成功后播放 0.28 秒跨屏飞牌反馈，仅为原型动画，不额外执行游戏逻辑。

扩大区域与快速松手的最终手感按最新要求移交真实素材阶段；
九点精度转入 [R2 探针](R2_TOUCH_PROBE.zh-CN.md)，
不将“可触摸”替代“全部命中误差 ≤8 像素”。

aim3 本轮证据：

- 本地与实机 34 项功能测试通过；5 项触摸接入门禁测试通过，
  故意移除启用/正常恢复/异常恢复或把启用提前到保存之前均会被阻止。
- 实机回放 `1789876683967076698` 的 1,069 步通过，回放结束时 277 次提交，
  45 次取消。包含 g=0/48/96、三起手位 × 五目标拖至 y=8、
  move/up 同一帧、边界松手取消和重叠不提交。
- 回放完成后，该会话另收到触摸输入并产生 7 次提交；最终计数为 284，
  不把额外输入计入自动回放断言或代替用户手感确认。
- 100 秒运行正常结束，末尾统计约 59.47 FPS，窗口 p95 17.48ms；
  已审视 y=8 时的双屏截图。它不等于 30 分钟长稳。

## 1. 隔离边界

- 卡二目录：`/mnt/sdcard/Ports/SlayTheSpireGeometryP1`。
- 独立入口：`/mnt/sdcard/Ports/Slay the Spire P1 Geometry.sh`。
- 来源：[原型源码和操作说明](../prototype/p1/README.zh-CN.md)。
- 无游戏素材、无音频初始化、无游戏 JAR、无存档路径，不启动 Java 或正式游戏。
- SDL2、SDL2_ttf、Python 和中文字体使用本机已有依赖，不安装系统组件。
- 不修改 Weston、设备树、udev、声卡静音状态；不挂载/卸载正式游戏运行库。
- touch2 仅在会话期间启用并恢复固件触摸模式，不更改持久化配置或校准数据。
- 单实例锁；其他游戏运行时拒绝启动；按 PID 与进程启动时间限制清理范围。
- SSH 验证时暂停自己接管的系统菜单；正常退出与异常恢复仅恢复相同身份的菜单。
- 退出监护独立于渲染；启动器意外退出时另有恢复进程处理渲染子进程和菜单。

## 2. 实现范围

| 项目 | 实现 |
| --- | --- |
| 实际输出 | 本固件实测两个 1024×768，横向位置 `(0,0)` / `(1024,0)` |
| 绘制 | 一个 2048×768 SDL2 帧缓冲，两个 1024×768 视口 |
| 瞄准坐标 | 纵向虚拟画布，上屏 y=0，下屏 y=768+g；默认 g=48，可调 |
| 原型画面 | 自制几何背景、目标、卡牌；下屏完整底图和装饰前景；非原生素材提取 |
| 目标布局 | 单、双、五目标、重叠、两侧包围 |
| 起手位置 | 左、中、右三张卡，手指按下锚点固定；浮动卡牌不移动瞄准原点 |
| 目标判定 | aim3 向上 48 像素，方向吸附区、0.14 弧度外沿吸附、0.035 弧度保持余量 |
| 歧义 | 多个角区间同时命中则不选，不按数组顺序猜测 |
| 同步反馈 | 唯一目标身份控制上屏高亮、下屏编号和箭头；目标还未显示则禁止提交 |
| 箭头 | 一条直线虚线，统一虚线相位，两屏分别裁剪；铰链不绘制；箭头尖端避开目标文字 |
| 手柄 | 左右选牌→A→左右选敌→A；B 取消；触摸接管后旧 UP 无效 |
| 触摸 | 按设备名发现，读取实际轴范围；Type-B 槽和 tracking id；不重复消费 SDL 合成鼠标 |
| 生命周期 | 第二指、SYN_DROPPED、失焦、设备断开、目标消失、拖回、边界松手取消 |

当前箭头是直线几何基线，不是最终原生曲线。角度吸附、上移门槛、卡牌大小和虚拟间距均待手感验证。
当前抽象目标的移除用于验证身份失效，不代表已接入真实游戏的死亡或召唤流程。

## 4. 本轮发现并修复

1. 系统同时消费触摸，触摸一次后产生失焦，导致后续按键不可操作。
   改为获焦时独占触摸 evdev，失焦/退出释放；内核自动回收异常退出后的独占。
   不独占按键，保留独立退出监护的事件读取。
2. UP 包可能携带最后一次坐标变化。先处理最终坐标，再校验已显示目标，
   防止松手时仍沿用上一次高亮误提交。
3. SYN_DROPPED 后必须查询所有槽的 tracking id/坐标和当前槽，
   清理队列与手势并等所有手指抬起，不能从丢失的半个手势恢复出牌。
   重连后的手势具有不同设备身份；卡牌使用独立固定实例编号，不以当前位置作为提交身份。
4. 箭头指向目标外沿，避免覆盖编号；手牌和浮动卡牌位于箭头前景。
