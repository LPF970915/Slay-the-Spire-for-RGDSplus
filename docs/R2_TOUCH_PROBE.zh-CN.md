## 2. 测量规则

九点坐标为 `x=16/512/1008`、`y=16/384/752`，从左到右、从上到下重复三轮，
共 27 点。取每次初次按下坐标，记录 dx/dy/欧氏误差，不吸附、不校正。
目标未呈现前不接受下一点；移动超过 12px 的点击单独取消。
误差大于 96px 视作错点并记录，不推进；8～96px 的误差保留在正式采样中。
因此不存在将偏移“吸附成零”的假通过。

软件结果的 `measured_pass` 仅表示本轮数值门槛达标；
`physical_verified` 始终为 false，需要操作者和证据台账另外签认。
来源明确区分 `physical-unconfirmed`、`evdev-injection`、`model-replay`。
操作者瞄准误差包含在结果中，不能将单次落笔偏差直接认定为硬件故障。

拖动页保留有界轨迹与实时坐标；跨出坐标范围、第二指、失焦、断连等清除在途触摸。
X 重测另建轮次，旧样本保留 JSONL；L/R 切页保留本轮网格结果；B 取消。

## 4. 人工验收

1. 从卡二 Ports 启动 R2，确认物理上屏为统计、下屏为网格，系统菜单不同时响应。
2. 点击金色十字中心并抬笔，每轮九点，共三轮；不要拖动点按。
3. 记录最大误差、错点数以及是否有固定方向偏移；日志自动保存，无须手抄所有点。
4. L 或 R 切换拖动页，沿横向、纵向、对角线和四边滑动，确认轨迹跟手且无跳变。
5. B 取消后重新拖动；第二指介入后抬起所有触点，确认新触摸可用且没有悬空状态。
6. 长按 Select/Back 约 1.5 秒退出，再次菜单启动，确认仍可触摸和退出。

连续 30 分钟运行另行计时，保留帧时间/RSS，并观察实体画面。
可参考 README 的日志路径；异常时先取证，不修改系统校准来掩盖原因。

## 5. 进入 R3 的门槛

R2 的屏序、原始触点/边缘和恢复由实机确认，软件无重复输入；
长稳结论有对应时长证据后，再启动真实游戏的隔离战斗接入。
R3 先移植按键路径及背景/前景归属，再接触摸目标和跨屏箭头。
原型 FPS、错误次数和目标身份不可直接作为真实游戏验收结果。
