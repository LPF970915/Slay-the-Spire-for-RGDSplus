# 1024×768 单屏渲染修复记录

记录日期：2026-09-20，中国标准时间 UTC+08:00。
设备日志使用 UTC，对应日志日期为 2026-09-19；两者是同一轮测试。

## 范围与结论

本轮修复单屏纹理损坏，不实现双屏。菜单和一个隔离的铁甲战士战斗场景有
实机缓冲区截图对照；这不等于 S3 全场景或 G-S 单屏总验收通过。
用户提供的 PC 截图只用于原生 4:3 布局参考，不作为掌机画面证据。

实测：

- 原生 `Settings.isFourByThree=true`，`isLetterbox=false`。
- 游戏逻辑、LibGDX、SDL 窗口和 drawable 均为 1024×768。
- 原生缩放：`scale=xScale=0.53333336`，`yScale=0.7111111`。
- 菜单的大面积条纹和黑色遮挡已在对照截图中消失。
- 隔离战斗的背景、前景、人物、敌人、手牌及战斗控件可见。
  小图集修正后，人物、小型敌人和顶部图标的细条纹消失。
- 保留原生单屏手牌位置，未提前做双屏手牌上移/放大。

## 两条损坏路径

### ASTC 输入字节布局

检查固定上游版本的 `libtexcompress.so` 与 `texcompress-agent.jar`：

1. JNI `nCompress` 的 ASTC 分支固定将通道数 4 传给压缩函数。
2. Java 侧既允许三通道 RGB 直接进入，也会把全不透明 RGBA 降为三通道 RGB。
3. 这让原生函数按错误步长读取，可能越过输入分配范围；
   错误像素和错误 alpha 随后被缓存、上传。

修正：

- 压缩前把 RGB 显式扩展成 RGBA，alpha 为 255。
- 保留原 RGBA 的透明度；通过 slice 保证 JNI 地址从实际像素起点开始。
- ASTC 模式禁用不透明 RGBA 降回 RGB 的优化。
- 调用原生 ASTC 前检查输入至少有宽×高×4 字节。
- 对不透明纹理加入缓存哈希域标识，旧错误条目不再命中。
  未受上述降通道问题影响的透明 RGBA 可以复用旧缓存。
- ASTC 与 ETC2 默认使用不同缓存目录，避免格式切换命中不匹配的旧条目。

Java 修正方法复制到目标类内部，不依赖应用类加载器中的帮助类。
这是因为上游压缩代理还会从 bootstrap loader 加载；只在普通 classpath
测试通过不足以保证实机可用。

### 小纹理 ETC2 回退

上游在纹理任一维小于 128 像素时从 ASTC 回退到 ETC2。
原游戏的铁甲战士图集为 611×113，小型敌人图集也命中此路径。
实机对照中，这些对象仍有细条纹；绕过该路径后恢复。

当前处理：小图集直接走原始非压缩上传，不删除资源、不裁剪角色。
本轮没有重写上游 ETC2 编码器，故结论限定为兼容性绕过已验证有效。

## 排除过的方案

| 对照 | 结果 |
| --- | --- |
| 仅关闭 `LIBGL_FORCE16BITS` | 菜单条纹仍存在，内存占用增加，不采用 |
| 改成 ETC2 并用独立缓存 | 色块/细条纹仍存在，内存余量偏低，不采用 |
| `LIBGL_MIPMAP=0` | 未消除主要条纹，不采用 |
| 全面关闭压缩、保留全部纹理尺寸 | 内存余量过低，主动终止，不采用 |
| 关闭压缩并全局缩小纹理 | 可排除大面积条纹，但字体变糊，仅诊断，不采用 |
| RGBA 输入修正、禁止降通道、小图集原始上传 | 菜单和隔离战斗对照通过，作为当前候选 |

不把缓冲区已有的坏像素称为显示面板扫描撕裂。当前仍保留上一版
SDL swap interval 0 和游戏 24 FPS 上限，避免回到约 1 秒一次换帧、
游戏跳过输入/逻辑更新的已知状态。没有新的实体屏幕视频证据，
不能宣称所有动态撕裂已经消失。

## 性能与安全边界

- 菜单和隔离战斗预热后，5 秒统计窗口约 120～121 次更新/提交；
  平均帧间隔约 41.67 ms。不是物理面板 FPS 或逐帧 P95/P99。
- 修正后菜单可用内存约 180 MiB；战斗后段一次采样为
  `VmRSS=537896 KiB`、`MemAvailable=122384 KiB`。
- 冷纹理重新编码和场景加载有秒级暂停；未计作稳定战斗样本，也没有隐瞒为无卡顿。
- 诊断截图是明确启用的一次性 GLES 回读，默认游玩不回读；
  截图帧不用于稳定性能结论。
- 正式存档留在卡二。战斗测试目录为 `/tmp/rgds-sts-render-check`，
  只复制档案/存档，程序与资源链接到已安装版本；没有第二个游戏实例。
- 测试后正式 `IRONCLAD.autosave` 与测试前备份的 SHA-256 一致。
- 最终通过模拟独立返回键长按退出；TERM 后触发 KILL，退出码 137，
  这是有意的应急退出测试，不计为自发崩溃。菜单进程已解除暂停。
- 设备保留适配层回退材料和存档快照于 `cache/render-backup-20260920/`。
