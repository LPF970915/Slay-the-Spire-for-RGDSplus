# R3 背景与小屏修订

日期：2026-09-20。开发分支：`codex/r3-small-screen`。
修改前标签 `r3-native-ui-baseline-20260920` 保持不动。

## 目标与范围

本轮先针对用户提供的 4.3 寸、1024×768 双屏使用条件改善战斗页面，
不改变游戏逻辑分辨率，不覆盖稳定单屏，不进入正式玩家存档测试。

- 上屏：原生完整战斗背景、角色与敌人、顶栏；不绘制原生装饰前景。
- 下屏：复制同帧完整无角色背景，包含原生底图、远景/墙体、背景光效，
  然后叠加原生装饰前景和下屏 UI。
- 手牌：5 张以内整体比例从 1.10 提到 1.50，上移量从 250 调到 315。
  6～7 张降为 1.30，8～10 张降为 1.12，避免大手牌整体超出视口。
  这些是第一轮审图参数，不代表大手牌实体体验已验收。
- 战斗控件：能量、结束回合、抽牌和弃牌图标整体 1.40 倍。
  牌堆锚点移入屏内，避免放大后裁掉边缘。
  能量球额外上移 24 像素，避免与左下抽牌堆图标贴合。
- 上屏信息：血条/血量/格挡及状态图标、敌人意图与伤害数字 1.30 倍。
- 顶栏、菜单、牌堆全页、其他房间暂时沿用原生大小，不宣称全界面已完成小屏适配。

## 实现约束

背景镜像仅在 `AbstractDungeon.render` 的原生 `renderCombatRoomBg`
调用期间启用，进入前和返回前排空 SpriteBatch。在 `SpriteBatch.flush`
里将同一 Mesh 的原生 GPU 绘图提交到另一视口，随后恢复上屏视口。
角色/战斗特效/UI 不在该作用域内。原生背景方法和游戏逻辑均不重复执行，
没有逐帧 CPU 读屏，也不创建额外背景纹理。

初版创建 Pixmap 纹理被现有 ASTC 代理压缩，导致复制目标不兼容、下屏黑底。
未压缩空纹理实验仍触发 GL4ES 的不兼容读回路径，因此最终去掉纹理复制方案，
改为仅镜像背景 Mesh 绘图提交，并加入静态回归检查。
失败截图只作排障证据，不作为完成预览。

手牌和控件的缩放、平移统一由 `UiTransform` 表达，卡牌文字仍使用投影层变换，
避免 FontHelper 重置变换矩阵导致文字与卡面分离。跨屏箭头起点使用同一手牌变换。
对应 Hitbox 登记同一逆变换；非手柄模式才在原生命中检查时换算指针，
检查后恢复原指针，不修改原生手柄的虚拟游标坐标。
在房间/页面切换时清空登记，平时复用变换并更新活跃控件；
页面弹出时停用战斗手牌变换，避免旧命中区域跨页面残留。

较长一轮初版测试出现内存压力和慢帧。本轮另将渲染状态/投影矩阵、指针检查栈、
常用手牌变换改为复用，避免增加每帧临时分配。新短稳结果与旧慢帧证据分别保留，
不因短测改善就宣称长期性能退化已解决。

触摸桥仍为 capture-only。逆变换数学测试与采集注入不等于真实点击/拖牌已接入；
后续触摸提交必须继续验证屏幕归属、owner、取消、真实卡牌与敌人身份。

## 验证纪律

- 构建期对 10 个真实游戏/运行库类执行转换检查。
- `UiTransformTest` 验证 0～10 张手牌、共 539 个正逆坐标样本及控件锚点；
  这是软件坐标检查，不是实体触点精度。
- 实机截图逐张检查完整背景、人物归属、文字与卡面一致、控件边缘和选敌箭头。
- 软件按键验证选牌、切换敌人、取消、出牌、打开/返回牌堆与结束回合。
- 保留实际帧时间、原生状态及退出审计；不以截图证明物理撕裂已消失。
- 全部截图和日志只留在私有 `validation/r3-native-ui/`，不上传 GitHub。
