## 本轮范围

按用户最新顺序推进：全界面接入 → 用户逐页调整布局 → 美术资源加载优化 →
真实触摸提交及交互反馈。最初逐页截图版为静音、仅采集触摸。
当前 `r4-touch-20260920-8` 接入原生音频、下屏点击与战斗拖牌，
默认 30 FPS、32/128 MB 堆、SerialGC、JIT tier 1、RAM 诊断。
本轮故障修复与证据边界见 [R4 触控与卡顿修复](R4_TOUCH_RUNTIME.zh-CN.md)。
未修改资源压缩、纹理质量或稳定单屏运行配置。

“接入”指原生绘制有明确上下屏归属，或有明确的下屏完整保留策略，
不是 U01–U33 的设计细节、全流程操作和实体触控已经全部验收。

## 实现边界

`ScreenRoutes.java` 对照本机正版 JAR 的 24 个地下城状态和 22 个菜单状态，
构建时检查集合完全一致。页面类按上屏、下屏、双屏只读复用登记，
再对场景内的按钮、角色、正文和预览分开路由。

- 原生游戏更新一次。背景、选中物件、地图等复用同一批 GPU 绘制，
  不为第二块屏幕再次调用页面 `render()`。
- `render()` 内可能创建升级预览、移动 hitbox、更新效果，因此不能视为纯函数。
- 顶栏与药水弹窗仍在上屏；独立详情的切换、升级开关在下屏。
- 主菜单改为贯穿塔景：上屏塔身与顶云/Logo，下屏放大的原生塔基/群山，中云两屏复用。
- 场景背景两屏复用，战斗装饰前景只在下屏，保留 R3 手牌和控件尺寸。
- 上屏焦点预览目前主要复用原坐标；居中、放大、文字排版交给逐页调版。
- 自定义绘制事件不能仅凭 `AbstractImageEvent` 继承关系放上屏：
  检查派生类是否重写 `render` / `renderAboveTopPanel`，有则完整保留下屏。
  翻牌和转盘因此不会丢失下屏点击对象。
- `pageId` 从原生状态判断，不由最后一个 render 调用决定；`seenPages`
  仅代表调用过渲染方法，不证明该页面实际可见或操作通过。
- 当前 R4 通过有序输入桥接入下屏点击与战斗拖牌/原生出牌。
  显式启用/恢复 tpctrl、动态 evdev、失焦取消、独立长按 Select 退出的链路不变。
  R3 和未显式启用 live 的 review 保留 capture-only；逐页实际触控仍需分别验收。

## 截图与验收方法

每页按顺序确认：进入 → 上/下屏归属 → 控件与必要文字完整 →
原生按键选择/确认 → 模态关闭 → 返回原页面。
之后再调整位置/尺寸；真实触摸精度和反馈另开验收，不与按键注入混记。

`validation/r4-all-pages/` 保存 framebuffer 原始横排截图、上下拼接截图、
对应状态以及输入来源。拼接图是 2048×768 framebuffer 重排为 1024×1536，
不是屏幕实拍，不能据此证明实体撕裂、屏幕顺序或触控精度。

可选截图导航只在 **R4 独立测试存档**、显式 `--page-probe` 时启用：
白名单包含原生菜单页面，以及空闲游戏中的地图/牌组/设置，操作在游戏线程执行；没有任意代码执行、
房间替换、奖励生成或强制结算。默认掌机入口不启用。
探针先初始化原生父面板，再打开子页，确保 B 返回路径完整。

```powershell
py -3 prototype/r3/device.py deploy --variant r4
py -3 prototype/r3/device.py run --variant r4 --page-probe --seconds 1800
py -3 prototype/r3/device.py page --variant r4 --page cards
py -3 prototype/r3/device.py shot --variant r4 --name unique-name
py -3 prototype/r3/device.py key --variant r4 --keys b b
py -3 prototype/r3/device.py stop --variant r4
py -3 prototype/r3/device.py audit --variant r4
```

SSH 密码从进程环境注入，不写入仓库。无需探针的自然流程测试省略
`--page-probe`，只使用原生按键导航。

## 门禁

- `prototype/r3/build.py`：46 个原生枚举值、83 个原生类转换及页面进出作用域，
  SpriteBatch 恰好两次 GPU 提交，539 个仿射采样，加原生二次曲线/箭身渐大/朝向/跨屏坐标/地图等比测试。
- `tools/test_r4_routes.py`：状态诊断、防止二次原生遮罩 render、探针白名单与隔离。
- 继续运行 R3 生命周期、触摸约束、P1 输入状态、启动 profile、heartbeat、
  打包与 Git 正版资源排除检查。
- 静态通过不等于界面实际到达、自然规则通过、实体触摸通过或全流程 25 FPS 通过。

本轮观测到的探针父菜单空列表异常保留在私有日志中，补齐父面板初始化后，
图鉴 → 单卡详情 → 图鉴 → 父菜单 → 主菜单的 B 返回路径已复测。
