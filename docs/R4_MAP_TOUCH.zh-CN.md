# R4 地图下屏触摸修订

日期：2026-09-22。构建：`r4-map-touch-20260922-1`。

## 本次实现

- 地图继续使用一份原生 `DungeonMapScreen` 状态和滚动偏移，不复制地图、
  不修改全局 `Settings.HEIGHT`，也不运行第二套地图更新。
- 下屏触摸按原生 lower-local 1024×768 坐标处理。
- 按下地图空白或节点后，移动超过 12 px 进入拖动状态；一旦进入拖动，
  本次抬手永远不会转成节点点击，即使拖回原点。
- 拖动偏移限制在当前原生 `mapScrollUpperLimit` 与
  `MAP_SCROLL_LOWER` 之间，边界从原生对象和静态字段读取。
- 同一触点按下、未拖动、同一节点抬起，才设置原生 `clicked`；
  合法性、路径连接、飞鞋、房间转换和随机结果仍由原版判断。
- Boss 节点也延后到抬手确认，不再按下即触发。
- 地图打开、关闭、失焦、第二指、B 接管或会话取消时清除手势状态。
- 合并的 MOVE 事件保存整段触点的最大位移，快速拖动不会因采样合并而
  被误认为点击。

## 软件验证

- `MapGestureTest`：点击阈值、拖动回原点、跨节点、空白拖图、边界、
  取消及合并 MOVE 位移通过。
- 实际三 agent 转换链包含 `DungeonMapScreen.update`、
  `updateYOffset` 和 `DungeonMap.update` 的地图触摸钩子。
- review 隔离存档的 framebuffer/evdev 注入验证：
  - 地图打开后下屏拖动改变滚动视图；
  - 拖出再拖回原点，`map.taps` 不增加；
  - 当前战斗未完成时点击非法节点，仍停留在 `MAP`；
  - B 返回后 `dungeon.screen=NONE`，手牌、能量和战斗状态未改变。
- 以上是软件注入证据，不是实体触点精度、合法节点自然流程或物理屏幕
  验收；当前 review 场景没有推进玩家战斗。

## 待真机确认

1. 从系统菜单启动后进入地图，手指上下拖动是否自然、边缘是否可控。
2. 拖动结束后不误点节点，轻点合法下一节点能进入对应房间。
3. 拖动和点击在上屏/下屏接缝附近不串位。
4. 地图返回、切房、B、Select 退出后触摸焦点与音频正常。
