# R2 设备输出与下屏命中探针

静音、无游戏资源、无存档访问。R1 几何原型和正式游戏不变。
启动卡二 Ports 中的 `Slay the Spire R2 Touch Probe.sh`。
独立目录为 `SlayTheSpireTouchR2`。R1/R2 不能同时运行。

## 实机操作

1. 物理上屏应显示 `R2 / 上屏` 与统计，下屏显示 `R2 / 下屏` 与网格。
2. 九点页每次点击金色十字中心并抬笔，按 1～9 顺序做三轮，共 27 次。
   接近四角的点距边界 16 像素。手不要拖动，中心与边缘都要测。
3. 统计自动保存。误差按初次按下坐标计算，不吸附、不平均修正、不写校准。
   单点误差目标 ≤8px；错误点击大于 96px 不前进，但记录错点，不能隐瞒失败。
4. L/R 切换到连续拖动页，横向、纵向、对角线和沿四边拖动，观察轨迹和坐标。
5. B 取消当前触点；测试第二指/回到新触摸后无悬空状态。X 开始新的测量轮次，
   旧轮次仍保留日志，不覆盖证据。
6. 长按 Select/Back 约 1.5 秒退出；渲染卡死时再等待最多约 3 秒清理。

只操作彩色十字；此探针不需要触摸上屏。
误差统计同时包含手指/笔的落点误差，不是自动校准结果。
完成三轮后请报告屏序、最大误差及有无明显边缘偏移。
“实触待签认”表示仍需操作者确认；即使软件误差为零也不自动标记实体验收通过。

## 日志与依赖

`logs/state.json` 每两秒记录 FPS、帧间隔 p95、RSS、输入状态和测量结果。
每次运行的 `*-result.json` 保存完整采样点；同次 JSONL 保留手势和取消。
`physical-unconfirmed`、`evdev-injection`、`model-replay` 分开标记；
软件注入和回放只证明后段输入链路，不能作为物理精度数据。
默认不截图；验证时可使用 `--capture`，避免常驻像素回读影响性能。

依赖本机 Python3、SDL2、SDL2_ttf 与中文字体，沿用已验证的 R1 模式启用/恢复、
evdev Type-B、焦点独占和独立退出。模式启用失败时 R2 拒绝进入测量。
不改 Weston、udev、设备树、永久模式或校准值，不启动 Java 或音频。

30 分钟无故障只能证明原型的运行/资源统计，不能替代物理面板视频检查，
也不能直接推断真实游戏的帧数或资源占用。
