# P1 双屏几何原型

这是独立、静音、无正版游戏素材的几何实验，不是双屏版正式游戏。
不读取或写入《杀戮尖塔》存档，不需要 desktop-1.0.jar，不修改系统显示配置。

## 运行

将包内 `Ports` 内容放到卡二的 `Ports` 目录，启动：

`Slay the Spire P1 Geometry.sh`

程序目录为 `SlayTheSpireGeometryP1`。先退出其他游戏再启动。
设备需要已有的 Python 3、SDL2、SDL2_ttf、Source Han Sans CN 字体和双屏 Wayland；
当前 RGDSplus 固件已提供这些依赖。没有携带或安装第三方运行库。

`touch2` 修订补齐小丑牌启动器的固件触摸模式处理：
启动时保存已知 `tpctrl` 值并显式写入 `0`；退出及启动器异常恢复时，
仅当当前值仍为 `0` 才恢复原值。未知值或接口缺失不写入，不修改永久配置。

## 操作

| 操作 | 输入 |
| --- | --- |
| 选牌、选敌 | 左/右 |
| 拿起卡牌、确认目标 | A；先拿牌，再选目标，再确认 |
| 取消 | B；拖回起始区域也会取消 |
| 上屏远程瞄准 | 从下屏任一卡牌向上拖，调整方向，看上屏高亮后在下屏松手 |
| 切换场景 | L/R，或点击下屏顶部 `<` / `>` |
| 重置当前目标 | X |
| 删除选中目标 | Y；未选中时删除最后一个目标 |
| 调整虚拟铰链间距 | L2/R2，每次 16 像素，范围 0～160 |
| 独立应急退出 | 长按 Select/Back 约 1.5 秒；冻结时再等待最多约 3 秒强制清理 |

卡牌方向必须明显向上，aim3 上移 48 像素进入瞄准。
只在高亮目标明确、当前目标仍有效、结果已经显示时提交。
重叠导致歧义时不出牌，改用方向键与 A 精确选择。
触摸期间按方向键或 A 会接管到手柄，需要再次明确 A 确认；
旧触摸松手不会替手柄提交。B 始终优先取消。

aim3 扩大了方向选敌范围：可以继续向下屏顶部拖动，不在顶部 12 像素处断开；
选中时为金色虚线，无目标/重叠时保留灰色方向线。快速甩牌并在屏内松手，
会先显示选中目标，再只提交一次，并有短暂飞牌反馈。
不要把笔划出实体屏幕；最外沿 2 像素处抬起仍按可能失联取消。
距顶部约 8 像素处仍可正常松手提交。

默认上屏为系统左侧输出，下屏为右侧输出。若物理屏序不同，
可从终端给 `launch.sh` 加 `--swap`；不会修改固件或触摸校准。
默认铰链间距 48 是待体验验证的逻辑参数，不是实测物理尺寸。

## 场景

单目标、双目标、五目标、重叠目标、两侧包围。
三张抽象卡牌分别检验左/中/右起手。
实线边框高亮、下屏目标编号、虚线箭头都来自同一个目标身份。
箭头在纵向虚拟画布生成，分别裁剪到横向帧缓冲的两个视口。

日志在程序目录 `logs/`；`state.json` 是周期性状态，`latest.log` 是最近一次运行日志。
默认不截屏。帧缓冲截图只在验证模式显式开启时产生。
所有输入与显示都由同一状态更新驱动；长按退出由独立监护进程处理。
`state.json` 的 `touch` 字段记录焦点、独占、阻塞状态和原始事件数量；
同次 JSONL 日志只记录前 128 个原始触摸事件，便于区分驱动没上报与解码/命中问题。
软件事件注入不经过实体触摸面板，不能作为物理触摸已修复的证明。

## 开发验证

在仓库根目录运行：

```powershell
py -3 -m unittest discover -s prototype/p1 -v
py -3 prototype/p1/make_replay.py
py -3 prototype/p1/make_package.py
py -3 prototype/p1/device.py deploy
py -3 prototype/p1/device.py run --seconds 70 --replay
py -3 prototype/p1/device.py fetch
```

设备工具交互询问 SSH 密码，或读取 `RGDSPLUS_SSH_PASSWORD`，不把密码写入文件。
测试注入仅用于自身运行中的 P1 会话，按 PID 与启动时间校验；
不要在原型的自动回放期间手动操作。

不包含：真实战斗规则、原生背景提取、药水/遗物/顶部菜单操作、跨场景移植、
最终美术/字体/卡牌尺寸、真实游戏帧数或单/双屏存档兼容验证。
